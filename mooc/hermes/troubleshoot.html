🩺 故障解决

常见问题排查与修复指南

快速诊断

遇到问题时，首先运行诊断命令：

$ hermes doctor # 全面诊断 $ hermes config check # 检查配置完整性

这两个命令能发现 80% 的常见问题。

常见问题与解决

1. 安装后运行 hermes 提示"命令未找到"

❌ 原因：安装脚本添加的路径没有生效。
解决：重新打开终端，或手动执行 source ~/.bashrc（Linux）/source ~/.zshrc（macOS）。

2. API 调用报错 401 Unauthorized

❌ 原因：API Key 未配置或已过期。
解决：检查 ~/.hermes/.env 文件中的 API Key 是否正确，确认 Key 在服务商后台仍然有效。

3. 模型返回空内容或报错

❌ 原因：可能模型选择不正确或 API 配额用完。
解决：运行 hermes model 检查当前模型，尝试切换到其他模型测试。检查 API 账户余额。

4. Gateway 无法连接 Telegram/Discord

❌ 解决步骤：
① 检查 Token 是否正确配置在 ~/.hermes/.env 中
② Discord 用户需在 Bot 设置中开启 Message Content Intent
③ 查看日志：grep -i "error" ~/.hermes/logs/gateway.log | tail -20

5. 工具不可用（如无法执行命令、读取文件）

❌ 解决：运行 hermes tools 进入交互界面，确保 terminal、file 等工具集已启用。启用后需要 /reset 刷新会话。

6. Gateway 后台服务经常停止

❌ 解决：
① SSH 登出后停止：运行 sudo loginctl enable-linger $USER
② WSL2 关闭后停止：在 /etc/wsl.conf 中添加 [boot] systemd=true
③ 崩溃重启：systemctl --user reset-failed hermes-gateway

7. WebUI 容器启动失败

❌ 常见原因：
① 权限问题：确保 WANTED_UID/WANTED_GID 与主机用户一致
② 端口冲突：ss -tlnp | grep 8787 检查端口占用
③ 首次启动需等 2-5 分钟安装依赖：docker logs hermes-webui --tail 20

日志查看

日志是排查问题的关键：

# Gateway 日志 $ grep -i "failed to send\|error" ~/.hermes/logs/gateway.log | tail -20 # Docker WebUI 日志 $ docker logs hermes-webui --tail 50 # 系统日志（如果使用 systemd 服务） $ journalctl --user -u hermes-gateway -n 50

重置与重装

如果问题无法解决，可以尝试以下操作：

备份并重置配置

$ cp -r ~/.hermes ~/.hermes.backup # 备份 $ rm -rf ~/.hermes/config.yaml # 删除配置 $ hermes setup # 重新配置

完全重装

$ hermes uninstall # 卸载 $ rm -rf ~/.hermes # 删除配置目录 # 重新运行安装脚本 $ curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
⚠️ 重装前务必备份 ~/.hermes/skills/（已安装技能）和 ~/.hermes/.env（API 密钥），避免丢失重要数据。
